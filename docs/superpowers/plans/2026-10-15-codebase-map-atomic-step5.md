> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reduce the eleven method units while preserving their complete behavior and consumer contracts, with one unit per commit.

**Architecture:** Keep the existing router, method units, owners and helpers. Tighten prose in its current owner, move extended rationale to the hand-written plugin documentation, and enforce decreasing unit and transitive reader ceilings in the existing load-budget test.

**Tech Stack:** Markdown, TOML and standard-library Python; the existing compiler renders all five hosts.

**Spec:** `docs/superpowers/specs/2026-10-12-xray-atomic-method-design.md`, step 5. Its former X-ray identities map to canonical Codebase Map identities under the approved migration.

## Global Constraints

- One commit per unit; do not combine unit rewrites.
- Preserve every rule and invariant. Retain exact helper commands, output paths, section selectors, canonical headings and declared team extensions.
- A runtime body states the rule and at most one line of reason; move longer rationale into `docs/plugins/codebase-map.md` without adding a runtime load of that document.
- Preserve the general perimeter, parsed stylesheet/cascade analysis, static-only boundary, three coverage figures, source immutability, provenance, run modes, coordinator publication and isolated analyst.
- Budgets only go down. Optional allowances remain frozen; do not use spare headroom as measured savings.
- No new registered skills, scripts, template layer, framework or dependencies. Do not rewrite adjacent entry/role units, legacy aliases, senior-review or parser behavior.
- Bump Codebase Map, the marketplace and skill-catalog while its generated index carries provider versions; regenerate packages and documentation together.
- Every commit runs repository gates on an LF extraction of that exact candidate. Structural host evidence remains separate from installed-host execution and actual cost.
- Continue in the authorized primary checkout on `master`. Preserve preexisting files, including publication lock bytes and concluded evidence.
- Step 4's required real classic comparison must be delivered before any unit edit. The bound Step 4 completion report is the entry receipt.

## Review Focus

- A consumer loads a bounded section without surrounding prose: its obligations must remain in that selected section.
- Optional comments, lite depth, updates and single-phase runs select different closures: measure their worst permitted profiles and preserve skipped sections.
- A report consumer searches exact headings: preserve skeleton names, order and extension anchors rather than shorten public labels.
- An interrupted or carried run contains incomplete or stale artifacts: preserve the mode, provenance, invocation stop and whole-mirror publication rules.
- A stylesheet, implicit dependency or project instruction sits outside the obvious parsed-source set: preserve the declared perimeter, target exception and actual source-reading requirement.

## Shared task interface and verification

Each task consumes the preceding commit's units and budgets. It produces one smaller unit, its decreased `UNIT_BUDGETS` entry in `tests/test_xray_load_budget.py`, any justified lower affected reader caps, and a preservation receipt. Unit counts use `len(text.split())`; reader counts retain the existing declared section/mode/conditional traversal. Task 1 adds all eleven whole-unit ceilings to that existing test owner. Later tasks lower only their unit entry, without increasing another ceiling.

For every task:

1. Capture the exact base commit, original unit bytes/count, applicable source/consumer contracts and current reader profiles in its own canonical run.
2. Lower the unit ceiling below the current count (Task 1 also introduces the eleven-unit census). Run the load-budget test and retain the expected over-budget failure before editing the unit.
3. Tighten only the named unit, preserving the listed obligations. Transfer any extended rationale into the hand-written documentation. Lower its cap to the resulting count and lower affected reader caps only when every conditional profile permits it.
4. Run the load-budget, method-unit, skeleton/consumer, analysis-owner, run-control, composition and host-rendering tests. Expected: all pass, identical required resources/headings and a smaller unit.
5. Obtain an independent preservation review against the original bytes, real consumers and all eleven behavioral cases under `evals/codebase-map/`. Fix any lost requirement before publication; this is distinct from compiler evidence.
6. Bump versions, regenerate the provider index, all five hosts and plugin documentation. Freeze an LF candidate from the base plus exactly the intended changes; preserve the primary's foreign paths.
7. Run all repository linters, documentation/instruction parity, compiler `--check --support`, Copilot guard, version-bump check and the complete unittest suite on that candidate. Inspect the changed nested instructions on all five rendered hosts. Expected: zero failures/errors; disclose platform skips. Verify every discovered module executed.
8. Check staged paths and bytes against the verified candidate; commit with the task's imperative message, push to `master`, and verify consistency/publication for that exact SHA. Complete the canonical result and ledger with measured unit/reader differences and limitations.
