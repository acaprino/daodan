# Codebase Map: linguaggi e strumenti

Aggiornato al 17 novembre 2026.

Lo snapshot analizza ogni linguaggio con un parser e risolve le chiamate con il risolutore lessicale. La pipeline (`docs/plugins/codebase-map.md`, sezione Pipeline) risolve poi ciò che il lessicale non prova con l'analyzer del linguaggio, l'indice di un indicizzatore letto per intero oppure il grafo dei fogli di stile, e aggiunge le chiamate che i test del progetto eseguono sotto il registratore dell'osservatore. La copertura si legge per linguaggio: siti con una risposta, per classe, buchi per classe, archi incerti, e lo stato `complete` oppure `lower-bound` (`docs/plugins/codebase-map.md`, sezione Copertura). Spec: `docs/specs/2026-11-08-risoluzione-chiamate-motore.md`.

## Limiti noti

- **JavaScript dinamico.** Su express le chiamate senza risposta sono metodi di `req`, `res` e `app`, oggetti che Express costruisce a runtime: nessuna analisi statica li tipizza.
- **TypeScript.** Dove un `include` prende sia `x.ts` (o `x.tsx`) sia `x.d.ts`, TypeScript tiene il primo e lascia fuori il `.d.ts`, che resta senza documento con il motivo e il file tenuto (`indexers/typescript.py`).
- **Python senza tipi.** Le chiamate su parametri non annotati (`store.get_file`) restano senza risposta.
- **Rust.** rust-analyzer gira solo nel container di Daodan, con build script e macro procedurali; senza container Rust è `unavailable` con la causa. Un build script che fallisce (una libreria di sistema che manca all'immagine) è una lacuna, e il suo crate resta senza ciò che genera. Una funzione che una macro genera non ha un punto nel sorgente: la sua chiamata resta un buco (`undefined-project-symbol`).
- **Go.** Una chiamata su un valore di funzione o su un'interfaccia anonima non ha una dichiarazione a cui arrivare. In un workspace, `go mod download` fallisce in ogni modulo che richiede un membro non pubblicato: `restore_failed`.
- **Java e Kotlin sotto il 17.** scip-java non indicizza su un JDK più vecchio (`jdk_unsupported`): la build si indicizza sul 17, e dove così non compila un secondo tentativo dichiarato alza i livelli o la toolchain (`build_edited`; `docs/plugins/codebase-map.md`, sezione Pipeline).
- **Java e Kotlin, file senza documento.** Un file Java dice perché nessun javac del build lo compila: un `excludes` o `testExcludes` di maven-compiler-plugin nel modello effettivo di Maven, un modulo che solo un profilo aggiunge al reactor, il build della sua cartella senza indice, nessun source set (`missing` in `indexers/java.py`). Un target JVM di Kotlin Multiplatform con un altro nome (`jvm("desktop")`) non si compila: il plugin di scip-java nomina solo `compileKotlinJvm` e `compileTestKotlinJvm` (`SCIP_GRADLE` in `indexers/jvm.py`).
- **C e C++.** Ogni file si legge con le macro dei file della sua unità di traduzione, cioè quelli che include e quelli che lo includono: una macro definita come decorazione (`#define local static`) o come involucro di prototipo (`OF((args))`) si cancella prima di leggere. Un'istruzione spezzata fra i rami di un `#if`, o una parola del compilatore in un ramo spento, è un errore di sintassi per tree-sitter: le sue righe sono una lacuna, il resto del file si legge (`docs/plugins/codebase-map.md`, sezione Linguaggi e parser). Un nome che il file non dichiara si risolve sull'unica definizione non `static` fra le dichiarazioni delle intestazioni di progetto incluse; con due definizioni, o in C++ con una funzione omonima in un namespace visibile, resta senza risposta. Un `#include <x.h>` non è mai un'intestazione di progetto. Una build MSBuild non dà un database di compilazione: le sue unità restano senza indice.
- **Passo dinamico.** Chiude un buco solo dove un test esegue la chiamata: un progetto senza test dichiarati, o con test che non partono, non aggiunge nulla, e la lacuna lo dice. Vue e Svelte non hanno osservatore. Valgrind non parte sotto il gVisor delle Sandbox di Modal: Rust, C e C++ lì sono `recorder_failed`, con la causa, e il driver dei benchmark dà agli osservatori nativi le VM Sandbox, dove parte.
