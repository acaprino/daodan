# Worktree Manager

Worktree Manager delegates Git workspace operations to the external
[Worktrunk](https://github.com/max-sixty/worktrunk) executable and adds Daodan task
identity, descriptions, tags and a persistent catalog. Worktrunk is dual licensed
MIT OR Apache-2.0; the local adapter is original MIT-licensed Daodan content.

Use `/daodan:worktrees` to list every checkout, including the main checkout,
external worktrees and detached revisions. Free text identifies an annotation
or task workspace operation. For example:

```text
/daodan:worktrees
/daodan:worktrees descrivi la task login come "Correggere timeout accesso" e aggiungi il tag urgente
/daodan:worktrees verifica gli aggiornamenti upstream di Worktrunk
```

New managed checkouts live under the main checkout's `.daodan/worktrees/`.
`.daodan/worktrees.json` stores annotations and creation identity. Git remains
authoritative for paths and branches, and Work Controller's agenda remains
authoritative for task progress and ownership. Running from a linked checkout
reuses the main home. Ignoring `.daodan` is a prerequisite to creation.

## Lifecycle

The delivery cycle composes the workspace method when a task uses worktree
isolation. Existing explicit branch/in-place policies retain their meaning.
Creation, setup, active-host binding, integration and cleanup have separate
outcomes. Retry reconciles an existing reservation instead of overwriting paths.
Annotating a foreign checkout does not make Daodan its owner.

The merge choice asks the user with Squash preselected. The existing review
owner checks the prepared result; a default Worktrunk merge is not substituted
for that review. Original task commits and review evidence are retained, and
removal requires scoped authorization and preservation of local data. GitHub
operations follow the delivery workflow and repository protection rules.

## Runtime and updates

The supported version and upstream source commit live in the plugin's
`skills/worktree-method/references/upstream.json`. The runtime helper verifies
the binary before use, with `git-wt` preferred on Windows to avoid Windows
Terminal's `wt` command. Upstream binaries and agent hooks are not bundled.

Upstream checks compare release metadata without changing the installation.
An upgrade is tested against the adapter's contract before its supported pin
and actual executable advance. The repository's `upstream-sync` workflow handles
this as external runtime maintenance rather than copied-source synchronization.
See the [intake decision](../superpowers/specs/2026-10-26-worktrunk-intake.md).

The provider's internal metadata can remain in the shared Git directory.
Generated host packages prove source adaptation, not active-host workspace
binding or every operating system's behavior. Those require separate probes.
