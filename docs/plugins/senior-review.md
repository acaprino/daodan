# Senior Review Plugin

Evidence-based review with focused specialists, a computed roster, isolated
worker contexts and one delivery ledger. The light shape uses one reviewer;
branch reviews keep the required floor and add specialists from measured target
signals. Registration makes a reviewer available; it does not run every reviewer
on every change.

Command examples use Claude notation. Other hosts use the bindings in the
source-derived reference below and [host setup](../hosts.md). `/daodan:review-changes`
and `/daodan:review-branch`, including lifecycle reviews, enter the same canonical
method. A caller-bound candidate retains its scope, baseline, snapshot and scoped
untracked content; missing comparison evidence remains a declared gap.

## Research basis for concise, effective agents

[Progetta prompt e agenti affidabili](../research/prompt-engineering-and-brevity.md)
collects the scientific references for this plugin's prompt and agent design:
atomic verifiable instructions, hierarchy and data boundaries, scoped evidence,
independent verification and end-to-end non-inferiority testing. Papers are
hypotheses to measure on this pipeline, not proof of the current architecture.
The same page links the separate EmbeddingGemma and code-search research.

## Specialist responsibilities

The source-derived inventory below links every registered role and its complete
method. The [specialist design](../superpowers/specs/2026-10-22-specialized-reviewers-design.md)
records the responsibility boundaries and qualification examples.

Each leaf owns a coherent mechanism and can be assigned independently. The
catalog includes security boundaries, persistent transactions/cache/representation/
retention, message delivery and remote effects, SQL/algorithm/asset/capacity/runtime
costs, observability/health/releases/environment/flags/recovery, accessible
navigation/perception, local correctness/concurrency and application subtraction.
Testing and stack leaves remain in their owning plugins.

`chicken-egg-detector` retains startup cycles and prerequisite ordering;
`temporal-resilience-auditor` owns progress and recovery over time;
`resource-lifecycle-auditor` owns acquisition and release; `ui-race-auditor` owns
UI event interleavings. `api-contract-auditor` checks authoritative boundary
contracts against producers, consumers, mocks and actual serialization;
`logic-integrity-auditor` checks domain invariants. The premise auditor remains an
independent process role with separate blind, challenge and claim-check modes.

Thirteen broad reviewer identities are generated presets assembled from canonical
specialists declared in their existing provider manifests. Ad hoc jobs use the
same leaves and delivery contracts for the assigned context. Registration and
generation establish availability, not behavioral qualification. See the
[delivery evidence](../research/review-quality/reports/2026-10-23-reviewer-composition-delivery.md)
for the exact verified stage. Canonical bodies own checks and evidence requirements;
the guide and catalog do not duplicate their checklists.

## Selection and delivery

Preparation resolves the exact candidate, available knowledge and the existing
`review_roster.py` result. The compiled reviewer catalog supplies registered
identities, triggers, prerequisites and host bindings. Source additions and
removals can activate specialists; relevant static presentation and deployment
paths also contribute signals. Unknown applicability is a gap, not a clean skip.

General `performance` requests resolve to `senior-review:performance-auditor`;
`react-perf`/`react-performance` name the React rendering specialist. These
responsibilities can both apply. Explicit requests are reconciled with the
computed roster and cannot bypass its floor or allowed dispatch. Shared-context
preferences and optional verification shortcuts do not remove required roles or
gates. Targeted file/directory scopes remain explicit; this change introduces no
new full/dir/doc selection engine.

Every selected reviewer receives its canonical body, scoped evidence and a unique
intermediate report path. Independent discovery receives no peer findings. The
blind premise result is accounted once; later premise challenges and verification
use separate contexts. Missing inputs or deliveries keep coverage incomplete.
Only the coordinator consolidates findings and publishes the final report.

Reports preserve source locations, triggers, impact, counterevidence, provenance,
uncertainty and coverage. Quantitative claims distinguish measurements from
static derivations. Empty replies, arbitrary quality scores and unchecked
checklist counts cannot establish a successful review. Review does not authorize
application edits, comments, commits or publication.

## Available domain knowledge

The required skill-catalog provider selects scoped knowledge from available
language, framework and domain skills. The run records provider/version,
fingerprints and assigned delivery IDs; reviewers return how that knowledge
was applied to source evidence. Missing or stale selected inputs are failed
coverage, while unknown inventory or unmatched scope remains an explicit gap.
Knowledge selection enriches existing reviewers within the same ledger.
