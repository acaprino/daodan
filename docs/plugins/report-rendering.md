# Report rendering

Report rendering produces an optional human view of an existing canonical
Markdown report. The agent writes domain content once; a fixed local renderer
supplies navigation, table filtering and responsive light/dark presentation.
The HTML is standalone, with bundled CSS and JavaScript and no external runtime
dependencies. Linked evidence and images retain their own availability requirements.

The `report-renderer` skill owns the helper's input/output contract. Consumers
load it by registered identity and declare the provider as required. Brand naming,
X-ray and review retain their native schemas, report sections, evidence,
uncertainty, source ownership and completion gates. Only the final report owner
creates the view; worker handoffs stay in their native formats.

Naming views let the reader explore Scorecard weights and recompute its Overall
row. The saved recommendation, criterion scores and screening evidence remain
unchanged. Unscored criteria contribute no weight, missing screening remains
visible, and resetting restores the original values.

The stdlib Python helper takes explicit input, output, profile and owned output
root arguments. It escapes raw HTML, preserves unsupported Markdown as visible
text, validates link schemes and refuses output traversal, links and source
overwrite. An existing destination requires intentional overwrite. The view
retains the original Markdown for source inspection and download.

This is original local work informed by
[agent-html-kit](https://github.com/leex279/agent-html-kit), inspected at commit
`7752a14097273e636e1e1955136c13914488e96a`. No upstream source or text is copied.
Token savings require a measured comparison with equivalent content, including
generation, edits and downstream consumption; a fixed renderer alone is not a
quantitative savings claim.

## Additional report owners

Project Knowledge adds views of instruction audits and documentation changes,
including creation and maintenance of AGENTS.md and CLAUDE.md. The coordinator
renders its run-owned report; durable instruction files retain their native
format and loading rules.

Project Lifecycle adds views of operation summaries, consultant handover dossiers
and final maintainer campaigns. Stage results, current versus historical checks,
dry-run limits and open decisions remain visible.

Testing adds views of the canonical test audit and consolidation report, with
HTML confined to the task's dedicated output root even when TEST_AUDIT.md lives
in a shared project directory. Cause classification, acceptance and quarantine
ledgers remain authoritative. A checkbox in the page does not accept an action.

These owners render after report verification and before run closure when HTML
is requested or navigation/comparison helps. An explicitly requested view that
fails remains an open deliverable. Small results keep their simplest format.
