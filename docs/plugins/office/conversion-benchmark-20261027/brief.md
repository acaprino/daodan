# Comparative mechanical HTML conversion

User-authorized experiment, 27 October 2026. Produce one attractive but graphically demanding synthetic three-panel HTML (1280x720 per panel,16:9), fully local assets/fonts, no external scripts/network. Same frozen source and contents for all raw conversion lanes; record any mechanical derivation separately. No manual visual repairs to converted files.

Features: asymmetric grid/flex, large type, gradient, deliberate decorative overlap, SVG chart/illustration, an existing owned PNG asset, native HTML table with merged/header cells, image crop, callout, long text, accented/symbol glyphs. Synthetic data clearly labeled. Three pages cover opening, dense evidence/table and process/detail. Source author uses Taste art knowledge only, not a new upstream workflow.

PPTX: compare dom-to-pptx2.1.2 and OpenSlide2.3.1 pinned internal DOM exporter if reachable; do not pretend an unsupported/private harness is a public converter. DOCX: compare existing WordCraft0.8.0 and docx/html9.14.0; optional mechanically inlined HTML variant distinctly labeled, never hand-designed per engine. Common target page geometry may be normalized identically and logged; no content/style/coordinate repair after conversion. Raw source remains immutable.

Pinned dependencies only under runtime, preserve package locks/licenses and source provenance. No global installs or plugin dependency changes; skip package install scripts and browser auto-downloads, use an installed/bundled browser where available. Only generated trusted local HTML; no untrusted URLs or external resource access. Record browser flags and limitations. No native-app window is required unless explicitly available headless automation.

Each lane records actual command/API, tool/package/browser/version, raw logs, input/output hashes, timings, warnings/errors, native XML text/table/image/shape evidence, and saved-file renders. Compare visual evidence with browser reference, editable semantic content separately from raster/vector illustrations, and converter vs renderer uncertainty. No beauty or token-saving score from file size. There is no comparable live LLM baseline, so token savings remain unmeasured. Report unavailable paths as such, preserve failed attempts.

Expected worker reports are in the run; fixture in inputs/source.html and inputs/manifest.json; each lane owns its driver/runtime/output subtree. Root owns process metadata, preview server/gallery and final synthesis. Runtime dependencies never become Office adoption by this experiment.
