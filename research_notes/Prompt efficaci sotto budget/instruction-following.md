# Instruction following, long-context behavior, and reasoning/token tradeoffs under prompt budgets

## What do IFEval, FollowBench, InFoBench, ManyIFEval, Tülu 3, LongBench, and RULER measure, and what do they actually establish?

### Takeaway

These artifacts measure different things. IFEval, FollowBench, InFoBench, and ManyIFEval measure compliance with explicit requirements; LongBench and RULER measure task performance over long inputs; Tülu 3 is a post-training recipe and evaluation study, not an instruction-following benchmark. None of them, by itself, establishes that a shorter prompt will be followed better.

### Cited Findings

- **IFEval: objective verification of a narrow, useful class of instructions.** *Instruction-Following Evaluation for Large Language Models* (Zhou et al., 2023) contains 541 prompts and 25 types of programmatically verifiable instructions, with one or more instructions per prompt. Examples include word counts, required keywords, JSON output, and paragraph structure. It reports prompt-level and instruction-level accuracy. Prompt-level success requires every instruction in the prompt to pass, while instruction-level success scores individual instructions. Strict scoring applies the checker to the original response. Loose scoring additionally tries transformations such as removing Markdown emphasis or an introductory/final line. The authors explicitly note that strict checking can produce false negatives and that loose checking can introduce false positives. **Evidence type and result:** a reproducible programmatic benchmark, with GPT-4 and PaLM 2 reported as initial baselines. **What it establishes:** compliance with the represented verifiable constraints for the evaluated models. **Boundary:** it does not measure factual correctness, helpfulness, unconstrained instruction quality, or all natural-language instructions. The benchmark is not a direct test of prompt compression or contradictory rules. [Paper](https://arxiv.org/abs/2311.07911) · [Official code and data](https://github.com/google-research/google-research/tree/master/instruction_following_eval)

- **FollowBench and InFoBench: finer diagnosis of constraint count and individual requirement failure.**
  - *FollowBench: A Multi-level Fine-grained Constraints Following Benchmark for Large Language Models* (Jiang et al., 2023) contains 820 instructions drawn from more than 50 NLP tasks. Its five constraint categories are Content, Situation, Style, Format, and Example. Levels 1 through 5 incrementally add one constraint to an initial instruction. Hard Satisfaction Rate (HSR) scores whether all constraints in an instruction pass; Soft Satisfaction Rate (SSR) averages individual constraint satisfaction; Consistent Satisfaction Levels (CSL) measures consecutive fully satisfied levels. Closed-ended cases use rules and open-ended cases use LLM judges, with human verification in construction and evaluation. Across 13 evaluated LLMs, performance declined substantially as levels increased. The authors report that GPT-4 and GPT-3.5 consecutively satisfied only around three constraints on average, while still outperforming the tested open-source models. Situation and Example were particularly difficult categories. **Evidence type:** mixed programmatic and model-judged benchmark. **Boundary:** open-ended scores depend on judges, and adding a level changes constraint content and prompt length as well as count. It is evidence about increasingly complex composed instructions, not a clean isolation of token count. [Paper](https://arxiv.org/abs/2310.20410)
  - *InFoBench: Evaluating Instruction Following Ability in Large Language Models* (Qin et al., 2024) contains 500 instructions decomposed into 2,250 questions. Its Decomposed Requirements Following Ratio (DRFR) scores the fraction of atomic requirements satisfied rather than assigning only one overall score. The paper compares DRFR with direct scoring and compares expert, crowd-worker, and GPT-4 annotation. The authors report higher reliability for DRFR and find GPT-4 useful as a lower-cost annotator. Across the six evaluated models, Content and Style scores were highest, Format intermediate, and Number and Linguistic constraints lowest. **Evidence type:** decomposed-requirement benchmark with human and model annotation studies. **Boundary:** GPT-4 is not an infallible oracle. The paper's error analysis includes spatial/checking failures and cases where GPT-4 marked a partially fulfilled requirement as satisfied. The benchmark diagnoses requirement-level compliance, not the effect of prompt brevity itself. [Paper](https://arxiv.org/abs/2401.03601) · [Official code and data](https://github.com/qinyiwei/InfoBench)

- **ManyIFEval: systematic scaling from one to ten instructions.** ManyIFEval appears in the peer-reviewed paper *When Instructions Multiply: Measuring and Estimating LLM Capabilities of Multiple Instructions Following* (Harada et al., 2025). It evaluates text generation with up to ten objectively verifiable instructions; the companion StyleMBPP benchmark evaluates code generation with up to six instructions. Across ten evaluated LLMs, performance consistently degraded as instruction count increased. The authors also fit regression models to estimate results for unseen combinations and counts. A logistic regression using instruction count predicted multiple-instruction performance with approximately 10% error on unseen combinations, and the authors report that 500 ManyIFEval samples were sufficient for their performance-estimation procedure. The earlier OpenReview version, *Curse of Instructions: Large Language Models Cannot Follow Multiple Instructions at Once*, explains the controlled construction: ten instances per base task vary the count from one to ten. **Evidence type:** programmatic multi-constraint benchmark plus regression analysis. **Boundary:** the result applies to the tested verifiable instructions and models. Increasing count also changes total input and output demands, so it does not isolate prose length. It does not test arbitrary mutually inconsistent instructions. [Peer-reviewed paper](https://aclanthology.org/2025.findings-emnlp.896/) · [Earlier paper](https://openreview.net/pdf/848f1332e941771aa491f036f6350af2effe0513.pdf)

- **Tülu 3: training evidence, including targeted verifiable-instruction data and an out-of-distribution check.** *Tülu 3: Pushing Frontiers in Open Language Model Post-Training* (Lambert et al., 2024) describes supervised fine-tuning, preference tuning, and reinforcement learning with verifiable rewards (RLVR). For precise instruction following, it uses IFEval's 25 constraint types to synthesize 29,980 Persona IF instruction-response pairs. The generation process begins with 33 manually written seed instructions and uses GPT-4o with personas. A separate IF-augmented set adds IFEval-style constraints to Tülu 2 prompts for DPO and RLVR. IFEval is part of the development evaluation suite, while IFEval-OOD is included in the unseen suite. In the unseen-evaluation analysis, the authors report that models generally overfit to IFEval and that instruction-following performance varies across categories. **Evidence type:** training-data ablations, post-training experiments, and development/unseen evaluation. **What it establishes:** a concrete way to train and evaluate precise constraint following, plus evidence that a development benchmark can be overfit. **Boundary:** it does not show that prompt wording or prompt shortening caused the results, and IFEval performance alone should not be treated as general instruction-following competence. [Paper](https://arxiv.org/abs/2411.15124)

- **LongBench and RULER: long-input task performance, not pure instruction compliance.**
  - *LongBench: A Bilingual, Multitask Benchmark for Long Context Understanding* (Bai et al., 2023; revised 2024) contains 4,750 test instances across 21 datasets and six categories: single-document QA, multi-document QA, summarization, few-shot learning, synthetic tasks, and code completion. It covers English and Chinese, with average lengths of 6,711 English words and 13,386 Chinese characters. The original evaluation covers eight LLMs. LongBench-E creates a more even length distribution to examine degradation by length. The authors report that GPT-3.5-Turbo-16k outperformed the tested open-source models overall but still struggled as context grew; retrieval-based compression helped weaker long-context models but did not close the gap to stronger ones. **Evidence type:** bilingual, multi-task automatic evaluation. **Boundary:** the authors state that ROUGE-L/F1 can misrepresent response quality, sometimes underestimating models that produce longer responses. They also explicitly state that LongBench performance is coupled with instruction-following capability. It therefore cannot attribute every long-context failure to context length alone. [Paper](https://arxiv.org/abs/2308.14508) · [Official repository](https://github.com/THUDM/LongBench)
  - *RULER: What’s the Real Context Size of Your Long-Context Language Models?* (Hsieh et al., 2024) uses 13 tasks in four categories: retrieval, multi-hop tracing, aggregation, and question answering. Sequence length and task complexity are configurable. The arXiv v1 experiments evaluate ten models with 500 generated examples per task and length. Despite near-perfect vanilla needle-in-a-haystack results, every evaluated model degraded substantially on RULER as length increased. Only four exceeded the paper's threshold at 32K, and almost all fell below it before their claimed context lengths. That threshold is the Llama-2-7B 4K score of 85.6%, so “effective context” is operational and threshold-dependent rather than an intrinsic model property. **Evidence type:** controlled, predominantly synthetic evaluation with distractors and configurable complexity. **Boundary:** strong synthetic control improves isolation but limits ecological coverage; the QA category does not make the whole benchmark equivalent to real-world long-document work. The original paper evaluates ten models, while the current official repository describes an expanded evaluation of 17 open-source models, so paper and repository results are different snapshots. [Paper](https://arxiv.org/abs/2404.06654) · [Official repository](https://github.com/NVIDIA/RULER)

### Inferences

- **Plausible guidance, not a demonstrated universal rule:** represent important requirements as atomic, testable constraints and track both all-or-nothing success and per-constraint success. This follows from the complementary IFEval, FollowBench, and InFoBench metrics, not from evidence that one prompt format is universally best. [IFEval](https://arxiv.org/abs/2311.07911) · [FollowBench](https://arxiv.org/abs/2310.20410) · [InFoBench](https://arxiv.org/abs/2401.03601)
- Use separate evaluations for constraint count, input length, evidence position, and task difficulty. The benchmark designs show that these factors are easy to confound. [FollowBench](https://arxiv.org/abs/2310.20410) · [LongBench](https://arxiv.org/abs/2308.14508) · [RULER](https://arxiv.org/abs/2404.06654)
- A claimed context window or strong IFEval score is insufficient evidence for a long, instruction-dense production prompt. Evaluate the actual model on the actual combination of context and requirements. [RULER](https://arxiv.org/abs/2404.06654) · [Tülu 3](https://arxiv.org/abs/2411.15124)

### Gaps

- These sources do not provide a single causal estimate of “accuracy lost per 1,000 prompt tokens” for instruction following.
- “Instruction density” is not standardized across them: ManyIFEval varies instruction count, FollowBench varies sequential constraint levels, InFoBench decomposes requirements, and RULER/LongBench vary long-input task demands.
- The reviewed benchmarks do not establish a universal maximum safe number of instructions. Results are model-, task-, constraint-, and decoding-dependent.
- No reviewed result shows that compressing a prompt while preserving its formal requirements necessarily preserves compliance. That hypothesis needs a controlled paired evaluation.

## What does “Lost in the Middle” show about position and relevant evidence?

### Takeaway

*Lost in the Middle* demonstrates position-sensitive use of relevant evidence in the evaluated 2023 models: performance was often best when the answer-bearing document or target key-value pair was at the beginning or end, and worse in the middle. It is evidence about retrieval and question answering over context, not direct proof that an instruction placed in the middle of a system prompt will be ignored.

### Cited Findings

- **Main demonstrated effect.** *Lost in the Middle: How Language Models Use Long Contexts* (Liu et al., 2023; arXiv v3) evaluates multi-document question answering and synthetic key-value retrieval while varying the position of relevant information. The authors observe a U-shaped curve on the evaluated decoder-only models: primacy and recency positions outperform middle positions, sometimes substantially. Explicitly extended-context models were not necessarily better at using their contexts. **Evidence type:** controlled position manipulations with held task content and distractor context. **Boundary:** the conclusion concerns the tested models, tasks, context lengths, and prompting setups, not every current model or every kind of instruction. [Paper](https://arxiv.org/abs/2307.03172) · [Official repository](https://github.com/nelson-liu/lost-in-the-middle)

- **The effect was not uniform across tasks and architectures.** Some models performed the synthetic key-value retrieval task perfectly, while others still struggled with targets in the middle. Encoder-decoder models were relatively robust to position only when evaluated within their training-time sequence length; beyond that length, they also exhibited a U-shaped curve. Base models without instruction fine-tuning also displayed the effect, showing that instruction tuning alone does not explain it. These are important mixed results against a universal “all long-context models lose the middle” claim. [Paper](https://arxiv.org/abs/2307.03172)

- **A position intervention helped one task much more than the other.** Query-aware contextualization, placing the query both before and after the documents or key-value pairs, enabled near-perfect synthetic key-value retrieval but changed multi-document QA trends only minimally. Thus, repeating or repositioning a salient query was not a general fix across the two evaluated tasks. [Paper](https://arxiv.org/abs/2307.03172)

- **Longer context is a tradeoff, not a monotonic benefit.** The paper's controlled experiments and open-domain QA case study motivate a distinction between adding potentially useful information and adding more material that the model must process. The demonstrated position degradation means that the ability to accept more tokens does not imply reliable use of every relevant item within them. [Paper](https://arxiv.org/abs/2307.03172)

### Inferences

- **Plausible prompt-design guidance:** keep critical evidence and requirements easy to locate, remove irrelevant material, and test alternative placements on the target model. The paper supports empirical placement testing, not a universal rule to put every rule first or last. [Paper](https://arxiv.org/abs/2307.03172)
- Do not blindly duplicate instructions at both ends. Query-aware contextualization's much stronger key-value result than multi-document QA result shows why an intervention that helps one retrieval format may not transfer to another task. [Paper](https://arxiv.org/abs/2307.03172)
- For shrinking prompts, the defensible hypothesis is that removing distractors may improve both input cost and evidence accessibility. The paper does not prove that shorter always beats longer when the removed content is useful. [Paper](https://arxiv.org/abs/2307.03172)

### Gaps

- The paper does not directly measure the position of policy rules, output constraints, or contradictory instructions.
- It does not establish whether present-day models retain the same U-shaped magnitude. The demonstrated results are tied to the models evaluated in the paper.
- It provides no universal optimal position and no general token threshold beyond which middle evidence becomes unreliable.

## Are there reliable findings on many or contradictory instructions, prompt length, and compliance?

### Takeaway

There is reliable, bounded evidence that compliance can degrade as the number of composed constraints increases, including at very high keyword-instruction densities. Evidence on contradictions is narrower: CFBench finds difficulty with mutually exclusive Chinese constraints, while instruction-hierarchy work concerns conflicts across privilege levels. Raw prompt length alone is not isolated well enough to support a universal brevity rule.

### Cited Findings

- **Many instructions: consistent degradation in two complementary designs.** FollowBench declines as constraints accumulate from levels 1 to 5, and ManyIFEval declines across ten evaluated LLMs as verifiable instructions increase from one to ten. The convergence across different datasets strengthens the conclusion that multiple simultaneous requirements can be harder for the evaluated models. It still does not identify a model-independent maximum or separate count from every correlate of count. [FollowBench](https://arxiv.org/abs/2310.20410) · [ManyIFEval](https://aclanthology.org/2025.findings-emnlp.896/)

- **High instruction density: IFScale pushes a narrow constraint type to 500 instructions.** *How Many Instructions Can LLMs Follow at Once?* (Jaroslawicz et al., 2025) introduces IFScale, a business-report task containing up to 500 keyword-inclusion instructions. Across 20 models from seven providers, even the best frontier models achieved only 68% accuracy at density 500. The authors report three degradation patterns (threshold, linear, and exponential), bias toward earlier instructions, and performance-latency tradeoffs. **Evidence type:** repeated programmatic keyword checking, with five runs represented in the reported degradation analysis. **Boundary:** this is one report-generation task with one unusually homogeneous constraint family. Its “density” should not be equated with hundreds of heterogeneous policies, and its primacy result should not replace the task-specific position evidence from *Lost in the Middle*. [Paper](https://arxiv.org/abs/2507.11538) · [Official benchmark and results](https://distylai.github.io/IFScale)

- **Contradictory instructions: CFBench measures recognition/handling within priority-aware constraint evaluation.** *CFBench: A Comprehensive Constraints-Following Benchmark for LLMs* (Zhang et al., 2024 preprint; ACL 2025) contains 1,000 curated Chinese samples covering more than 200 real-life scenarios and over 50 NLP tasks, with 10 primary constraint categories and more than 25 subcategories. Its contradictory-constraint category explicitly includes mutually exclusive requirements that cannot all be satisfied. The authors report that many evaluated models struggled with this category. **Evidence type:** curated benchmark with multi-dimensional criteria and requirement priorities. **Boundary:** impossible requirements do not have a single all-constraints-satisfied correct answer; scores reflect the benchmark's annotated handling criteria. The paper also acknowledges evaluation-model bias and limited exploration of reasoning models. Chinese, real-world-derived CFBench results should not be generalized to every language or conflict type. [Paper](https://arxiv.org/abs/2408.01122) · [ACL 2025 version](https://aclanthology.org/2025.acl-long.1581.pdf) · [Official repository](https://github.com/PKU-Baichuan-MLSystemLab/CFBench)

- **Privilege conflicts are a different demonstrated problem.** *The Instruction Hierarchy: Training LLMs to Prioritize Privileged Instructions* (Wallace et al., 2024) defines desired behavior when higher- and lower-privilege instructions conflict and trains models to ignore lower-privileged malicious instructions. The authors report substantially improved robustness, including on attack types absent from training, with minimal degradation on standard capabilities. **Evidence type:** training intervention plus prompt-injection, jailbreak, system-message-extraction, generalization, and over-refusal evaluations. **Boundary:** this does not tell us how an untrained model should resolve two contradictory user requirements of equal authority, nor does it show that a shorter conflict description is easier. [Paper](https://arxiv.org/abs/2404.13208)

- **Prompt length and compliance are related but not interchangeable.** LongBench and RULER demonstrate degradation on long-input tasks, and LongBench explicitly warns that its scores mix long-context and instruction-following capability. Conversely, IFEval's prompts were manually checked to avoid conflicts, so IFEval compliance cannot be used as evidence about contradictory instructions. These boundaries rule out a simple syllogism that “long prompts degrade, therefore every long instruction prompt fails because of length.” [LongBench](https://arxiv.org/abs/2308.14508) · [RULER](https://arxiv.org/abs/2404.06654) · [ManyIFEval earlier paper describing IFEval construction](https://openreview.net/pdf/848f1332e941771aa491f036f6350af2effe0513.pdf)

### Inferences

- **Plausible guidance:** reduce redundant rules, reconcile conflicts before inference, state explicit precedence, and separate requirements from source material. These are risk-reduction hypotheses grounded in the count and conflict results, not guaranteed accuracy interventions. [ManyIFEval](https://aclanthology.org/2025.findings-emnlp.896/) · [CFBench](https://arxiv.org/abs/2408.01122) · [Instruction Hierarchy](https://arxiv.org/abs/2404.13208)
- When many requirements are necessary, evaluate per-rule omission as well as whole-prompt success. A single aggregate score can hide whether a model missed one rule or failed the entire task. [IFEval](https://arxiv.org/abs/2311.07911) · [FollowBench](https://arxiv.org/abs/2310.20410) · [InFoBench](https://arxiv.org/abs/2401.03601)
- Test compression as a controlled transformation: same requirements, same evidence, same model and decoding settings, varying only wording and token count. The reviewed results do not substitute for that experiment.
- A concise prompt can reduce input-token cost by construction, but an accuracy improvement is a separate empirical claim. Long-context degradation alone does not prove that the concise version will be followed better.

### Gaps

- No reviewed paper isolates natural-language prompt token count while holding every rule, example, evidence item, and output demand constant.
- There is no universal demonstrated policy for same-authority contradictory instructions. CFBench measures annotated handling; the instruction-hierarchy paper addresses different privilege levels.
- The evidence does not justify fixed limits such as “never exceed ten rules.” ManyIFEval and IFScale measure degradation, not a universal cliff.
- Position findings differ by task: IFScale reports earlier-instruction bias in its high-density keyword task, while *Lost in the Middle* often finds both primacy and recency advantages for relevant evidence. A single placement rule is not established.

## What is known about chain-of-thought, least-to-most, ReAct, skeleton-of-thought, and chain-of-draft versus direct answers in accuracy, tokens, and latency?

### Takeaway

Longer reasoning is most consistently useful for mathematical, logical, symbolic, compositional, or environment-interactive tasks. On many non-symbolic tasks, direct answers can be nearly as accurate while avoiding extra generated tokens; that is an efficiency win, not proof of universally higher accuracy. Chain-of-draft targets concise reasoning, while skeleton-of-thought targets parallelizable long answers and is explicitly unsuitable for some short-answer or step-by-step cases.

### Cited Findings

- **Direct answering versus chain-of-thought: strong gains are task- and scale-dependent.**
  - *Chain-of-Thought Prompting Elicits Reasoning in Large Language Models* (Wei et al., 2022) provides few-shot reasoning demonstrations. Across three large models and arithmetic, commonsense, and symbolic tasks, it reports substantial gains. In the highlighted GSM8K result, PaLM 540B with eight CoT exemplars reaches about 57% solve rate versus about 18% with standard prompting. The authors describe the benefit as emerging at sufficiently large model scale and note the serving cost of relying on large models. **Evidence type:** controlled prompting comparisons on reasoning benchmarks. **Boundary:** this does not show universal gains for small models, factual recall, classification, or arbitrary instruction following. It also does not show that the generated rationale is faithful merely because the final answer improves. [Paper](https://arxiv.org/abs/2201.11903)
  - *To CoT or not to CoT? Chain-of-thought helps mainly on math and symbolic reasoning* (Sprague et al., 2024 preprint; ICLR 2025) combines a quantitative meta-analysis of more than 100 papers with experiments on 20 datasets and 14 models. It finds strong benefits primarily for math or logic and much smaller gains elsewhere. On MMLU, direct answering was almost identical to CoT unless the question or response contained an equals sign, a marker associated with symbolic operations. Much of CoT's formal-reasoning gain came from symbolic execution, and CoT underperformed a symbolic solver. **Evidence type:** literature meta-analysis plus direct experimental comparisons. **Boundary:** the authors discuss long-horizon planning and dataset contamination as limitations; results remain tied to the included models, prompts, and datasets. The defensible conclusion is selective use, not “direct is always better.” [Paper](https://arxiv.org/abs/2409.12183) · [Official code](https://github.com/Zayne-sprague/To-CoT-or-not-to-CoT)

- **Least-to-most: decomposition and sequential solution improve complex generalization in the evaluated tasks.** *Least-to-Most Prompting Enables Complex Reasoning in Large Language Models* (Zhou et al., 2022 preprint; ICLR 2023) first decomposes a problem into subproblems and then solves them sequentially, using earlier subproblem answers. The paper reports improvements over standard and chain-of-thought prompting on symbolic manipulation, SCAN compositional generalization, and math reasoning experiments, including last-letter concatenation. **Evidence type:** task accuracy comparisons using prompted decomposition and sequential solving. **Boundary:** these results establish task performance for the evaluated models and compositional problems, not a general token or latency advantage over direct answering. Decomposition creates additional stages and intermediate context, so any efficiency claim needs separate end-to-end measurement. [Paper](https://arxiv.org/abs/2205.10625)

- **ReAct: reasoning plus external actions is not comparable to a pure direct-answer prompt.** *ReAct: Synergizing Reasoning and Acting in Language Models* (Yao et al., 2022 preprint; ICLR 2023) interleaves reasoning traces with environment actions and observations. On HotpotQA and FEVER, Wikipedia interaction is used to address hallucination and error propagation associated with CoT; the paper reports ReAct combined with CoT self-consistency as the best prompting configuration, rather than showing ReAct alone dominates every variant. On ALFWorld and WebShop, ReAct exceeds imitation- and reinforcement-learning baselines by 34% and 10% absolute success rate respectively, using one or two in-context examples. **Evidence type:** knowledge-intensive tasks with a Wikipedia API and interactive decision-making benchmarks. **Boundary:** tool quality, environment, number of actions, and orchestration affect both success and latency. The results do not justify ReAct for a self-contained simple question or establish a universal token/latency ranking against direct answers. [Paper](https://arxiv.org/abs/2210.03629) · [Project and code](https://react-lm.github.io/)

- **Skeleton-of-thought: latency improvement through parallel answer expansion, not a general reasoning-accuracy method.** *Skeleton-of-Thought: Prompting LLMs for Efficient Parallel Generation* (Ning et al., 2023) first generates an outline skeleton, then expands points in parallel. Across 12 evaluated LLMs, the paper reports speedups up to 2.39× and answer-quality improvements in many, not all, cases. Crucially, the authors state that SoT is not suitable for questions requiring step-by-step reasoning or needing only a short answer; SoT-R adds a router to trigger it selectively. **Evidence type:** end-to-end generation-latency measurements plus answer-quality evaluation. **Boundary:** “answer quality” is not identical to factual accuracy, and the paper includes LLM-judge evaluation. Speedups depend on batching/concurrency, model serving, answer length, and overhead. The 2.39× figure is a maximum, not a guaranteed average. [Paper](https://arxiv.org/abs/2307.15337)

- **Chain-of-draft: concise intermediate reasoning can preserve accuracy with far fewer output tokens in the reported experiments.** *Chain of Draft: Thinking Faster by Writing Less* (Xu et al., 2025) asks for minimal, information-dense intermediate steps rather than verbose CoT. Across its arithmetic, commonsense, and symbolic reasoning experiments, the authors report accuracy matching or exceeding CoT while using as little as 7.6% of the tokens, with corresponding cost and latency reductions. **Evidence type:** direct prompting comparisons of accuracy, generated-token counts, and latency. **Boundary:** 7.6% is a best-case “as little as” figure, not a universal average. CoD is still explicit intermediate reasoning, so its results do not demonstrate that a direct answer beats all reasoning. The findings are from the evaluated prompts, models, and tasks and should not be extrapolated to every reasoning model or open-ended task. [Paper](https://arxiv.org/abs/2502.18600) · [Official code and data](https://github.com/sileix/chain-of-draft)

### Inferences

- **When concise direct answers outperform in efficiency:** use direct answering when a paired evaluation shows equal accuracy and the task does not benefit from intermediate computation. The MMLU result in *To CoT or not to CoT?* supplies a concrete case where extra CoT adds generated tokens with almost no accuracy change. It does not show direct answering universally has higher accuracy. [Paper](https://arxiv.org/abs/2409.12183)
- **When longer or structured reasoning is justified:** mathematical, logical, symbolic, and compositional tasks have the strongest positive evidence. If a symbolic solver is available, the comparison should include it because prompted CoT underperformed the solver in the cited analysis. [CoT](https://arxiv.org/abs/2201.11903) · [Least-to-Most](https://arxiv.org/abs/2205.10625) · [To CoT or not to CoT?](https://arxiv.org/abs/2409.12183)
- **When interaction is justified:** ReAct is a candidate only when external actions or observations add information or change the environment. Its benefits cannot be inferred from token count alone. [ReAct](https://arxiv.org/abs/2210.03629)
- **When concise reasoning is preferable to verbose reasoning:** CoD is a tested candidate for reducing output tokens while retaining task accuracy; SoT is a candidate for long answers whose sections can be generated in parallel. Neither result supports applying its method indiscriminately. [Chain of Draft](https://arxiv.org/abs/2502.18600) · [Skeleton-of-Thought](https://arxiv.org/abs/2307.15337)
- Compare end-to-end cost, not just visible rationale length. Include prompt tokens, generated tokens, number of model calls, tool latency, parallelization overhead, and final-answer accuracy. The methods change different components of that system cost.

### Gaps

- The reviewed papers do not provide one shared head-to-head benchmark of CoT, least-to-most, ReAct, SoT, CoD, and direct answering on identical models, tasks, decoding settings, and serving infrastructure.
- The least-to-most and ReAct accuracy results do not by themselves establish their net token or latency tradeoffs against direct answering.
- The CoD token result is an original-paper result; these notes do not establish independent replication across unrelated models and tasks.
- There is no universal evidence that longer reasoning reduces accuracy on non-symbolic tasks. The stronger demonstrated claim is often little or no accuracy gain, making direct generation more efficient.
- No reviewed method guarantees a faithful explanation, correct use of every instruction, or improved compliance merely because its final-answer accuracy improves.
