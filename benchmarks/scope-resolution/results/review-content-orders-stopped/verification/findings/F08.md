# F08: The validation pipeline runs after its subject is consumed, and its result is discarded

- Severity: Medium
- Confidence: 85
- File: `benchmarks/scope-resolution/app/packages/orders/service.py`
- Line: 27
- Description and evidence: Order of calls: reserve (:25), total (:26), then `self._pipeline.step(order)` (:27) with the return ignored, while :3-4, :11 and :20 describe it as replaceable validation. A replacement that raises leaves stock debited; one that returns a normalized copy changes neither stock, total, ledger nor notification. The default stamps validated=True on any order.
- Suggested fix: Run `order = self._pipeline.step(order)` first, then reserve and price from its result.
- Load-bearing premise: `step` runs after both `reserve_stock` and `compute_total`, and `checkout` does not use its return value.
- Also declared by other reviewers of this finding: in `checkout`, stock mutation and pricing both happen before any pipeline code runs, and no consumer uses the return of `step`. / no check of payload shape or range precedes `inventory.reserve_stock` on any route into `checkout`.
