# F07: A holder that dies leaves ledger.lock behind and every later ledger write fails

- Severity: High
- Confidence: 90
- File: `benchmarks/scope-resolution/app/packages/orders/ledger.py`
- Line: 15
- Description and evidence: The lock is a directory entry removed only by the holder's own finally (ledger.py:19-21, :31-33). Process death, or `os.close` raising before the unlink, leaves it on disk. After a restart every checkout raises FileExistsError after decrementing stock and every refund raises, until someone deletes the file by hand.
- Suggested fix: Use a kernel-held lock on a permanent file that is never unlinked, in one context manager used by both writers.
- Load-bearing premise: nothing other than the holder's own `finally` ever removes `ledger.lock`, and that `finally` does not run when the process is killed.
- Also declared by other reviewers of this finding: no code path removes or overrides a `ledger.lock` left by a holder that no longer exists. / no code removes or expires a `ledger.lock` left by a dead process.
- premise_provenance: independent
- Trigger: SIGKILL, default-disposition SIGTERM, OOM kill, TerminateProcess, os._exit or power loss between lock creation and unlink.
- Counterevidence checked: No other use of LOCK_PATH, startup cleanup, atexit or signal handling in app/; no pid, mtime or TTL in the file; ordinary exceptions do run finally and are not reported; no host process exists in app/, so restart policy is unknown.
- introduced_by_candidate: not applicable on content basis
- evidence_class: derived
