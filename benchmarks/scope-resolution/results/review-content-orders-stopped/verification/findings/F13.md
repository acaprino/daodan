# F13: A missing or null order id is stored as an ordinary id

- Severity: Medium
- Confidence: 85
- File: `benchmarks/scope-resolution/app/packages/orders/ledger.py`
- Line: 18
- Description and evidence: ledger.py:18 and :30 write `order.get('id', '?')`: missing becomes `?`, explicit None becomes `None`. Checkout requires only sku and qty. Two such orders produce identical rows and `?\tREFUND` cannot be tied to any sale: money in the register belongs to no identifiable order.
- Suggested fix: Require a non-empty id at the start of checkout and refund_request, before any effect; drop the placeholder.
- Load-bearing premise: an order without an id reaches the ledger write without being rejected.
- Also declared by other reviewers of this finding: an order without `id` reaches `ledger.record` and is written with `?` rather than refused.
- premise_provenance: independent
- Trigger: A checkout or refund_request payload with no id or with id None.
- Counterevidence checked: api.py:4 passes payloads unchanged; DefaultPipeline.step checks nothing; no earlier id access in service.py; no docstring allows anonymous orders, though the `?` default is deliberate in the code.
- introduced_by_candidate: not applicable on content basis
- evidence_class: derived
