# Optional dependencies for higher-fidelity multi-language parsing.
# The scripts themselves require Python >= 3.12 (stdlib only), and that floor is
# enforced rather than documented: the Python grammar `ast` uses is the running
# interpreter's, so an older one rejects every file written with newer syntax
# (PEP 695 `type X = ...` and PEP 701 f-strings both need 3.12) and records it
# with no symbols. `snapshot.py`, `analyze_file.py`, `doc_review.py` and
# `mcp_server.py` refuse to start below it, and their PEP 723 `requires-python`
# header lets `uv run --no-config --no-project --script <script>.py` provision a
# compliant interpreter instead.
# Measured over 22,536 files in evals/codebase-map/python-parser/RESULTS.md.
#
# Without these, the analysis scripts still work:
#   - Python uses the stdlib `ast` module (always available).
#   - Java / JavaScript / TypeScript / Rust / Go fall back to regex-based extraction.
#   - SQL / PL-SQL always use regex-based DDL extraction (tree-sitter is never
#     used for them).
#
# With these installed, Java / JS / TS / Rust / Go get tree-sitter accuracy
# (correct handling of nested classes, generics, JSX, decorators, lifetimes).
#
# Install with:
#   pip install -r requirements.txt
# or with uv:
#   uv pip install -r requirements.txt

# The Python bindings changed API incompatibly before 0.23 (Language/Parser
# constructors). The loader in languages/_treesitter.py targets the >=0.23 API
# and is tested through 0.26.
tree-sitter>=0.23

# >=1.0 is the Rust-core rewrite. The loader only calls get_parser(), which is
# stable across the rewrite (get_language()'s return type changed in 1.9).
tree-sitter-language-pack>=1.0
