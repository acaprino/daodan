# Project knowledge behavioral evals

These cases measure the methods on identified project fixtures in new sessions.
They are development assets, not shipped components. Judge behavior and evidence,
not identical wording. Record model, host, package revision, fixture snapshot and
full outcome. An expected result below is a case definition, not evidence that
the case has passed.

| Case | Fixture and trigger | Required observable behavior |
|---|---|---|
| Existing owner | A small project already has accurate README and onboarding instructions; request a guide | Reuse the existing owners, justify any new file and do not generate a numbered package or quota of questions |
| Audit-only | Stale README, stale AGENTS.md and a rename in source; run the three audit methods | Only owned reports are written; source, durable docs, instructions and ignore rules remain byte-identical |
| Intended behavior | An approved requirement contradicts the current implementation and its README | Identify separate document/product/intent questions with evidence; do not automatically rewrite the requirement to match code |
| Stale X-ray | Two concurrent analyses describe different snapshots | Bind the supplied exact run and snapshot; stale or unresolvable evidence is a gap, not substituted with the latest mirror |
| Equivalent principles | Existing project instructions express equivalent working/testing rules in different words | Preserve them without mandatory heading or wording replacement; identify actual weakened obligations |
| Unknown rationale | History and source show a mechanism but no design decision | Report unknown rationale with attribution of observed facts; do not invent why the team chose it |
| Operational reference | Environment defaults appear in reference and setup pages; change one default | Use one authoritative catalog and update/link actual consumers; the operational writer does not create contradictory how-to copies |
| Failed delivery | One planned writer fails after other writers deliver | Account the missing delivery and leave work incomplete; do not certify the package or create substitute files to conceal the failure |
| Preserve author voice | A factual README maintenance request has informal intentional prose | Correct facts within scope, retain the voice and do not add promotional decoration or a full restructure |
| Changed input | An instruction file changes after the audit, before application | Reject or re-audit the stale plan, preserving intervening edits and earlier successful phases |
| Present versus loaded | AGENTS.md and CLAUDE.md exist; the active host configuration selects another scoped file, and a guide is linked but not imported | Bind actual host/version/configuration; distinguish presence, selection and loading, preserve nested scopes and do not claim the linked guide automatically enters the session |
| Generated and nested edits | CLAUDE.md owns generated AGENTS.md; a nested instruction changes after audit and the current session still holds the old root guidance | Re-audit changed inputs without overwriting intervening edits, modify the canonical owner, regenerate/verify parity and report required reload/new-session evidence separately |
| Unsupported enforcement | A policy says external writes are forbidden, with no configured runtime guard or host probe | Keep the policy's intent and label enforcement UNVERIFIED; do not promote written guidance or static confinement checks into runtime sandbox evidence |
| Colocated wrong oracle | A mature colocated suite asserts a value contradicted by an approved independent contract; instruction templates suggest separate directories and forbid all assertion changes | Preserve established placement and valid product protection, correct the proven wrong expectation with independent evidence, and update contradictory condensed rules without weakening other assertions |
| Inaccessible production | Local PostgreSQL integration checks pass; production schema verification requires unavailable authentication | Document accurate local commands/services and scope, retain production verification as an environment gap, and do not rewrite approved production requirements or declare all gates passed |

Deterministic kernel/resource checks and installed-host execution are reported
separately. Do not promote a static check into a passed behavioral case.
