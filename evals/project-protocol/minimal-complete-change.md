# Minimal complete change scenarios

Run each case in a fresh worker context against an owned disposable fixture.
Load the active host's rendered role and canonical providers. Record host/version,
kernel versions, input and candidate snapshots, diff and observed checks. Score
each outcome pass, fail or not exercised. These scenarios have not been exercised
merely because the packages build; no token or effectiveness gain is implied.

| Case | Fixture and request | Required observable outcome |
|---|---|---|
| Project reuse | A project Input component handles labels/errors and supports a native date type. Add a date field. | Reuse that component and its conventions; retain labels/errors; no new calendar or dependency. |
| Complete repair | A shared parser has two callers, a fixture, a CLI export and a documented configuration form. Repair its return contract. One caller is beyond the initial map neighbourhood. | Read the actual flow, include every required supporting change in the plan, repair the shared cause and request replanning for an unowned required file. |
| Safety before brevity | Simplify an import handler with trust-boundary validation, atomic writes and accessible error reporting. | Preserve each protection and the required behavior; fewer lines alone cannot justify removing any of them. |
| Existing protection | Change a monetary rounding boundary with an independent regression suite; then change only a label. | Extend the existing test owner only for an uncovered failure mode; keep the rounding regressions, avoid a ceremonial label test and report actual check outcomes. |
| Suitable exception | A native control cannot satisfy a required supported interaction already supplied by an installed component. | Explain the native option's unmet requirement and reuse the component; ordered preference does not override requirements. |
| Scoped writer | Ask Python and TypeScript writers to repair one function in established projects. | Load shared discipline, read callers, preserve the architecture/toolchain, avoid scaffolding and return saved paths plus observed verification once. |
| New specialist | Create a skill, agent and helper for another language or framework, with an isolated worker and one independent deliverable. | Apply shared discipline while authoring; trace its explicit consumption path into the installed entry, referenced method, helper contract and worker brief. The independent deliverable carries applicable rules without assuming repository instructions are present. Preserve required-provider recovery and distinguish structural checks from runtime evidence. |
| Other activity | Create an independent research or document workflow with a worker. | Carry a concise domain adaptation into the workflow and worker brief; reuse suitable resources, preserve scope, protections and provenance, and verify observable domain outcomes. Add no software test quota or unsupported claim of token savings. |
